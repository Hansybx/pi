# 安全策略

本文档应当指导你理解 Pi 背后的安全概念，以及边界在哪里。

总体上，Pi 是一个在运行它的用户的安全边界内本地运行的编码 agent。监控它的操作，或把它限制在容器、虚拟机或其他沙箱方案内，是用户的责任。

Pi 把本地用户账号以及该账号可写的文件视为与 Pi 进程本身处于同一信任边界内。如果攻击者能修改用户主目录、工作区、shell 启动文件、环境或 Pi 配置下的文件，他们通常就能影响 Pi 或其他本地开发工具。依赖此类先期本地写权限的报告不算安全漏洞，除非它们展示了 Pi 如何授予该写权限，或跨越了操作系统权限边界。

Pi 依赖用户安装可信的扩展、加载可信的技能，并且只在可信仓库中使用 pi。这是因为像 `AGENTS.md` 这样的文件或注释中的指令可以轻易地对编码 agent 实施提示注入，而这无法防护。

## 报告漏洞

如果你认为在 pi 或本仓库的其他包中发现了安全漏洞，请通过以下任一方式私下报告：

- 发送邮件至 `security@earendil.com`，或
- 通过本仓库的 GitHub Security Advisories 提交私密报告

请包含：

- 问题的描述及其影响
- 复现步骤、概念验证或相关日志
- 受影响的包、版本、提交或配置
- 任何已知的缓解措施

不要为安全敏感的报告开公开 issue。我们会评审报告，并酌情协调披露。

## 范围

分发包、命令行工具、API 和仓库代码中的安全问题在范围内，`pi.dev` 上由 earendil 运营的基础设施也在范围内。

## 范围之外

- 本地代码执行或沙箱行为（Pi 编码 agent 有意不设沙箱）
- 用户安装的 pi 扩展或技能的行为
- 在不可信仓库中工作带来的风险
- 安装不可信扩展、技能、包或工具带来的风险
- 由不可信的 MITM 代理造成的问题
- 将 Pi 安装暴露在公网
- 提示注入攻击
- 泄露的第三方/用户控制的凭证
- 要求具备在目标机器上创建、修改、删除或替换文件、目录、符号链接、环境变量、shell 配置或其他用户控制的本地状态的能力的报告。这包括 `~/.pi`、`~/.pi/agent/models.json`、工作区文件、`AGENTS.md`、技能、扩展、扩展配置、dotfiles，以及通过 NFS、漫游配置文件或 dotfile 管理器同步的文件，除非报告展示了 Pi 本身如何授予该访问权限。
- 由故意削弱的用户配置导致的问题。
- 需要可信的本地输入/配置才能对 pi 编码 agent 发起的资源/DoS 主张。
- 关于恶意模型输出的报告。
- 用户批准或用户发起的本地操作被当作漏洞呈现的报告。

## 给报告者的说明

最有用的报告展示当前可复现的安全边界绕过，并给出已证实的影响。只展示预期的本地 agent 行为、提示注入，或恶意可信扩展/技能的报告，在此模型下不算安全漏洞。

例如，报告展示写入可信 Pi 配置文件的恶意内容导致 Pi 执行命令、加载攻击者控制的工具、把凭证发送到攻击者控制的端点，或以其他方式改变行为，属于范围之外。

如果可能，请包含确切受影响的路径、包版本或 commit SHA、配置，以及针对最新发布版或最新 `main` 的概念验证。对于依赖相关报告，请包含证据说明所交付的依赖确实受影响，且该问题可通过 Pi 可达。对于凭证泄露类的报告，请包含证据说明该凭证归 Earendil 所有，或可授予对 Earendil 运营的基础设施或服务的访问。
