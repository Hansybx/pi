# Pi 如何工作

Pi 协调模型请求、工具执行、上下文组装和会话存储。会话是 Pi 对一次对话的记录，包含消息、工具调用和结果、模型变更、压缩以及其他事件。

会话中的消息和事件构成一棵树。穿过该树的每条路径是一个分支。结束于当前条目的分支是活动分支，它为下一次模型请求提供历史。

## agent 循环

提交的消息会被添加到活动分支。Pi 根据系统提示词、活动分支、可用工具和模型设置构建模型请求，然后通过选中的 provider（提供商）发送。

provider 流式输出助手回复，其中可以包含文本和工具调用。Pi 记录该回复，执行每个工具调用，并记录结果。这完成一个轮次。如果工具结果或排队的消息需要又一次模型请求，Pi 会开始另一个轮次。否则，本次运行结束。

引导消息在当前助手轮次之后进入。后续消息在 agent 完成其待处理工作之后进入。中止会停止当前运行，并把排队的消息返回到编辑器。

## 上下文

活动分支提供对话历史。Pi 把它的会话条目转换为模型兼容的 user、assistant 和 tool-result 消息。

Pi 从其基础指令和发现的上下文文件构建系统提示词。请求还携带工具定义和技能描述。

完整的技能指令按需加载。扩展可以添加指令或转换上下文。

提示模板在编辑器输入成为用户消息之前对其进行展开。选中的文件、图像、粘贴的文本和 shell 输出都可以成为消息内容。

## 会话

持久会话是 JSONL 文件。每个树条目都有一个 ID 并指向其父条目。当前条目标识活动分支。

从较早的条目继续会在同一个文件中创建另一个分支。fork 和 clone 会把选定的历史复制到新的会话文件。

模型上下文由活动分支重建。压缩会插入一个摘要条目，它在后续的模型请求中替代较早的消息。原始条目仍保留在会话树中。

## 接口

交互模式在终端中渲染会话和 agent 事件。print 模式运行一个提示并写出最终回复。JSON 模式把 agent 事件写成 JSONL。

RPC 模式从 stdin 接受 JSONL 命令，并把响应和事件写到 stdout。TypeScript SDK 在进程内创建和控制 agent 会话。

所有接口都使用相同的 agent 和会话机制。

## 扩展和资源

扩展是加载到 Pi 进程中的 TypeScript 模块。它们的工厂函数注册工具、命令、快捷键、provider、事件处理器、渲染器和终端 UI。

技能提供按需的指令和支持文件。提示模板提供可复用的消息文本。主题提供终端颜色。Pi 包通过 npm 或 git 分发这些资源。

## 信任和权限

Pi 在加载项目设置和资源之前解析项目信任。在信任决定和项目资源加载之后，Pi 加载上下文文件。启用的工具使用 Pi 进程的操作系统权限。扩展在该进程内执行。
