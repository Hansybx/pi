# 会话和上下文

Pi 把一次对话保存为一个会话。该会话的活动分支为下一次模型请求提供对话历史。使用会话命令继续工作、探索另一个分支，或减少发送给模型的历史数量。

## 继续或切换会话

除非使用 `--no-session` 启动，否则 Pi 会自动保存会话。

```bash
pi --continue
pi --resume
```

`--continue` 打开当前目录最近的会话。`--resume` 打开会话选择器。在交互模式下，`/resume` 打开同一个选择器，`/new` 开始一个新会话。

每个会话记录其创建时的工作目录，且永不更改。Pi 在会话的工作目录中运行会话，因此工具、`@path` 引用、项目配置和上下文文件都从那里解析。

| 入口 | 工作目录 |
|---|---|
| `--continue` | 当前目录 |
| `--resume`、`/resume`、`--session`、`/import` | 会话的工作目录，可能与当前目录不同 |
| `--fork`，或你选择要 fork 的来自另一目录的 `--session` ID | 当前目录，位于新会话中 |

如果会话的工作目录已不存在，例如项目文件夹被重命名之后，交互模式会询问如何打开它：

- **Continue** 在当前目录中运行该会话。Pi 不会保存该选择，因此下次打开该会话时会再次询问。
- **Fork** 把会话复制到当前目录，作为一个带新 ID 的新会话，类似 `--fork`。原会话保持不变。启动时，该副本会像当前目录的其他新会话一样被存储；从 `/resume` 或 `/import` 触发时，它会像 `/new` 一样存储在会话旁边。
- **Cancel** 保持当前会话打开，或在启动时退出。

其他模式会以错误退出。

使用 `/name` 或 `--name` 指定一个易识别的会话名称。运行 `/session` 查看当前会话文件、ID、消息数、token 用量和费用。

会话选择器让你搜索、重命名和删除会话。它还可以显示路径、更改排序，并把结果限制为已命名的会话。关于其快捷键，参见[快捷键](keybindings.md#sessions)。

## 选择如何分支

Pi 把条目存储为树，因此返回较早的位置不会擦除你离开的分支。

| 操作 | 结果 | 适用场景 |
|---|---|---|
| `/tree` | 在当前会话文件内移动 | 相关的备选方案应归在一起 |
| `/fork` | 从较早的用户消息创建新会话 | 该备选方案应成为独立的工作 |
| `/clone` | 把活动分支复制到新会话 | 你想要当前状态的独立副本 |

在 `/tree` 中，选择一条用户消息可把其文本放回编辑器。编辑并提交它即可创建另一个分支。选择助手回复或其他条目会在该条目之后继续，编辑器为空。

当你离开一个分支时，Pi 可以对其进行总结，并把该摘要附加到你进入的分支。这样可以在不包含被放弃路径中每条消息的情况下保留其中的相关工作。

关于持久化的树和条目类型，参见[会话格式](session-format.md)。

## 管理对话上下文

模型接收的是活动分支，而不是会话文件中的每个分支。Pi 把该历史与系统提示词、发现的上下文文件、可用工具和已加载的技能描述组合在一起。[Pi 如何工作](how-pi-works.md#context)描述了这些输入如何组装。

页脚显示当前上下文用量。当活动上下文接近模型上限时，Pi 通常会压缩较早的历史。压缩会添加一个摘要并保留最近的消息。它不会删除原始会话条目。

运行 `/compact` 手动压缩。当摘要需要保留特定主题或决定时，你可以添加指令。通过[设置](settings.md#compaction)配置自动压缩和保留的历史。

如果 provider（提供商）不可用或无法接受总结请求，压缩可能失败。解决 provider 的问题后再次运行 `/compact`。禁用自动压缩不会禁用该手动命令。

关于阈值、保留边界、分支摘要行为和扩展钩子，参见[压缩参考](compaction.md)。

## 控制会话存储

默认情况下，Pi 把会话存储在 `~/.pi/agent/sessions/` 下，按工作目录归类。使用 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR` 或 `sessionDir` 设置选择其他位置。CLI 选项的优先级最高。

使用 `--no-session` 进行一次临时运行。临时会话在 Pi 退出后无法恢复。

## 导出或分享会话

使用 `/export` 把当前会话写为 HTML 或 JSONL。使用 `/share` 上传它并获得查看链接。默认情况下，配置了 Radius 认证时 Pi 使用 Radius 产物；否则使用私有 GitHub gist。将 [`sessionShareDestination`](settings.md#sessions-and-context) 设为 `gist` 或 `radius` 可强制指定一个目的地。

请先检查导出或分享的会话。它们可能包含提示、模型回复、工具参数、命令输出、文件内容和扩展消息。

## 报告 bug

运行 `/bug [description]` 为 Pi 开发者准备一份私密报告。你可以包含会话记录、省略它，或让当前模型总结问题。请检查任何会话记录或生成的摘要，因为它们可能包含敏感的对话数据。

报告包含环境和 provider 配置（不含凭证值），以及记录的错误诊断。通过 `radius.pi.dev` 上传它，或把同一份报告导出为 zip 以便自行检查和分享。上传不需要登录；Radius 认证会把报告归属到你的账户，以便开发者跟进。如果上传失败，Pi 会提供导出 zip 的选项。
